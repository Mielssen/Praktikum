# TravelManager — Інформаційна система управління туристичною агенцією

## Призначення проєкту
**TravelManager** — це вебзастосунок, створений для автоматизації повсякденних бізнес-процесів туристичної агенції. Система оптимізує роботу менеджера та спрощує взаємодію з клієнтами.

**Основні завдання, які вирішує застосунок:**
* Централізоване зберігання та управління базою доступних турів (напрямки, вартість, опис, дати).
* Облік клієнтів та оформлення бронювань.
* Оперативний доступ до актуальної інформації про статус замовлень.
* Надання зручного REST API для взаємодії клієнтської частини з сервером.

## Структура проєкту та архітектура
Застосунок побудований за принципом кліент-серверної архітектури з використанням шаблону проєктування MVC/API-орієнтованого підходу.

* **Backend (`/TravelManager.API`)**:
  * `Controllers/` — контролери для обробки HTTP-запитів (турів, бронювань, клієнтів).
  * `Models/` — сутності бази даних та моделі передачі даних (DTO).
  * `Data/` — контекст бази даних та конфігурації Entity Framework Core.
  * `Services/` — бізнес-логіка застосунку.
* **Frontend (`/wwwroot` або клієнтська частина)**:
  * Статичні файли (HTML5, CSS3, JavaScript).
  * Динамічне завантаження даних та взаємодія з бекендом за допомогою **Fetch API**.

## Технологічний стек та залежності

### Backend (ASP.NET Core Web API)
* **Платформа:** .NET (C#)
* **Головні бібліотеки та NuGet-пакети:**
  * `Microsoft.EntityFrameworkCore` (OR-мапер для роботи з БД)
  * `Microsoft.EntityFrameworkCore.Tools` та `MySql.EntityFrameworkCore` (або `Pomelo.EntityFrameworkCore.MySql`) для зв'язку з MySQL.
  * `Swashbuckle.AspNetCore` (Swagger UI для тестування та генерації документації API).
  * `Serilog.AspNetCore` та `Serilog.Sinks.File` (організація структурованого логування подій сервере).

### Frontend
* HTML5, CSS3 (з використанням кастомних стилів та сучасних макетів).
* Vanilla JavaScript (ES6+, асинхронні запити через Fetch API).

### База даних
* **СУБД:** MySQL Server.
* Підхід до проєктування: Database-First (або Code-First) із використанням міграцій та реляційних зв'язків між таблицями (Клієнти, Тури, Бронювання).





## Інструкція із запуску проєкту

### Вимоги до оточення
* **.NET SDK** (версія 8.0 або новіша).
* **MySQL Server** (версія 8.0+).
* **MySQL Workbench**, **DBeaver** або інший клієнт для БД.
* **Git**.

### Покроковий запуск

* **1. Налаштування бази даних**:
  * Переконайтеся, що служба **MySQL Server** запущена.
  * Створіть базу даних: `CREATE DATABASE TravelManagerDB CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
  * У файлі `TravelManager.API/appsettings.json` вкажіть ваш пароль та рядок підключення у секції `"ConnectionStrings"`.

* **2. Застосування міграцій**:
  * Перейдіть у каталог бекенду: `cd TravelManager.API`
  * Застосуйте міграції для створення таблиць: `dotnet ef database update`
  * *(Якщо утиліту ще не встановлено, виконайте: `dotnet tool install --global dotnet-ef`)*

* **3. Запуск застосунку**:
  * Запустіть проєкт командою: `dotnet run`
  * **Клієнтська частина (Frontend):** відкрийте `http://localhost:5000/` або `https://localhost:7000/`
  * **Документація API (Swagger UI):** відкрийте `http://localhost:5000/swagger`
